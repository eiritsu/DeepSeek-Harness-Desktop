# @deepseek-ai/dsh-client-ui-settings-archived-sessions

[English](README.md) | 中文

## 概述

使用**已归档**设置分区查看全部已归档会话，并按所属工作区分组。该页提供搜索框、工作区筛选和三种排序方式——按更新时间、按创建时间、按字母顺序；每行都可恢复到侧栏或永久删除，另外还有批量删除，但只在明确作用范围并两次确认之后才执行。页面自身不保存任何归档状态：它读取工作区快照与会话列表，并发出与侧栏相同的取消归档和删除命令。

<a id="use-this-package"></a>
## 使用本包

在设置里打开**已归档**。工具栏负责收窄列表：搜索框匹配会话标题的大小写与重音不敏感子串，工作区下拉列出注册表里的每个工作区及其归档数量，排序下拉先说明排序依据再说明当前生效的顺序。三种顺序分别是按更新时间、按创建时间和按字母顺序；由会话列表自行构建的行——宿主列表不携带的子代理——没有持久的创建时间，因此在创建时间顺序中排在所有有时间的行之后，而不是拿自己的更新时间顶替。折叠工作区分组只隐藏其行，不丢弃筛选条件，再次展开后视图不变。

每行的恢复控件调用宿主的取消归档命令，删除控件打开一个指明该会话的确认框；在勾选确认复选框之前，破坏性按钮保持禁用。行的两个命令在悬停和键盘聚焦时淡入，在没有悬停能力的设备上则始终可见。窄设置面板把行排成两行——标题占第一行，日期与命令共占第二行——因此不会有单元格被丢弃或遮挡。宿主接受的删除会关闭该确认框——行通过控制器自己的事件离开，本页不会再对它发起第二次删除。宿主拒绝的删除则保留确认框并清空复选框，因此重试需要重新确认，拒绝也会被报告。命令进行中时确认框不可关闭，因为关掉它只会把仍在进行的工作藏起来。

批量删除只作用于当前视图——工作区筛选和搜索词决定其覆盖哪些会话，第一个对话框在第二个对话框要求确认之前说明该范围和数量。该范围在对话框打开时就已冻结：期间变化的筛选无法扩大已确认运行会删除的集合，两个步骤上显示的数量始终描述同一批会话。删除逐条执行，整个运行期间对话框保持打开且不可关闭，部分失败的运行会报告成功数与失败数。

本页沿用官方设置页的页面框架，两个下拉触发器沿用 `Input` 组件的尺寸框，并沿用共享的悬停显示方式：行的命令以淡入淡出而非卸载或隐藏来显示，因此保持自身宽度且仍可聚焦。窄窗口下，设置框架保留带文字的导航，同时为内容列腾出更多空间；工具栏会换行排列控件，会话行则把标题放在日期与命令上方。本页样式表不声明任何自有颜色或字体——每种颜色都是 `--dsw-alias-*` token，每个尺寸都是下限或省略号。

客户端组合中需要 `dsh-client-ui-settings-archived-sessions` 才能显示**已归档**导航项；缺少它的组合不显示该项。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

本包以 id `archived-sessions`、order 40 注册一个 `settings.section` 条目，其 `inject` 面绑定工作区快照源、会话列表 observable，以及页面发出的两个命令：取消归档单个会话、删除单个会话。宿主半侧是一个空的 `apply`，只为让本包占一条 Loader 行，客户端模块系统据此送出浏览器半侧。

列表是 `archived-view.ts` 里的一段纯投影。`deriveArchivedRows` 把注册表全局的 `archivedSessionIds` 与会话列表的 `byId` 及工作区的 `sessionIds` 联结起来，因此行的标题与时间戳来自会话控制器，其分组来自工作区控制器；会话列表尚未描述的归档 id 会被跳过。`filterArchivedRows` 施加工作区选择和搜索词，比较双方都先分解为 NFD 并去掉组合记号再比较，因此不带重音输入的搜索词也能命中带重音的标题。`sortArchivedRows` 按时间、按创建时间或按大小写与重音不敏感的排序器排序，并依次以时间和会话 id 作决胜使每种顺序都是全序；没有持久创建时间的行在创建时间顺序中排在所有有时间的行之后，因为未知时刻无法放到时间轴上。`groupArchivedRows` 按注册表顺序为每个工作区输出一组，无工作区者排在最后。`archivedReadStatus` 在两个读取来源都稳定之前报告 `pending`，使首次读取期间的空归档不会被当成真的没有归档。

本地状态只包含宿主不拥有的部分：搜索词、所选工作区、排序、折叠的分组键、进行中的会话 id、两个对话框的打开状态，以及最近一条提示。所选工作区若在选中期间被删除，会在其选项消失的那次渲染上把视图收窄为未筛选列表，因此没有控件能指称列表已不再提供的筛选。批量对话框每次删除挂载一次而不是切换开关，因此每次打开都从范围步骤开始且确认复选框未勾选；它持有的是一份冻结的会话 id 集合而不是筛选的投影——两个步骤显示的数量与这次运行删除的集合是同一批会话。进行中的命令让其对话框保持打开且无法关闭，`RiskConfirmation` 组件的 `cancelDisabled` 一次性覆盖取消按钮、关闭按钮、页面遮罩与 Escape。行时间戳复用共享的 `relativeTime` 分桶，使侧栏与本页对同一时刻的称呼一致；只有文字来自本页字典。

`archivedReadStatus` 只在工作区流彻底停止时报告 `failed`，此时页面显示该失败而不是列表。它不提供重试：工作区控制器拥有重连，且没有发布任何能恢复终态流的操作，所以这里重试只能重新读取会话列表，并把用户指向一次无济于事的重新加载。

</details>

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **本地构建的行没有可排序的创建时间**——会话列表会自行构建一些行，即宿主列表不携带的子代理，它们不带持久头部。本页把它们列在创建时间顺序的最后，而不是当作纪元时刻，也不拿它们的更新时间顶替，并且不显示它们各自的创建时间。
- **批量删除是串行且不可续跑的**——中途失败的运行会报告数量但不重试；剩余会话保持归档，需重新打开对话框。
- **恢复或删除的行靠控制器自己的事件离开**——页面不做乐观移除，因此在跟随流尚未到达时该行会继续显示。
- **工作区流断开会隐藏列表**——页面显示失败块而不是最后一次已知的归档，并且不提供恢复手段；重连由工作区控制器负责。
- **运行时不变量：**不发布伴生。除读取两个快照和发出两个命令之外，本页不拥有任何关系。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者工作上下文——点击展开</summary>

本页读取两个彼此独立的来源，这一区分是关键：工作区控制器拥有哪些会话被归档及其名称，会话控制器拥有它们的标题与时间戳。把 `archived-view.ts` 里的联结保持为纯函数，把失败判定保持在 `archivedReadStatus`；会话列表没有失败阶段，主机不可达时它停在 pending。

两条删除路径都经过 `RiskConfirmation`：单条直接使用，批量则在标明范围的一步之后使用。两条都遵守两条规则：宿主接受的删除关闭其对话框，已经发出的命令则保持对话框打开，因为关掉对话框只会把仍在进行的工作藏起来。批量范围必须保持为对话框打开时捕获的冻结 id 集合——若用当前筛选的投影，两个步骤之间一次筛选变化就能删掉第一次确认从未展示过的会话。

有两条样式规则是关键性的，并且都针对样式表文本断言，因为 jsdom 既不排版也不求值媒体查询。行的命令只能在 `@media (hover: hover)` 内部隐藏：触屏设备永远不会触发本该显示它们的悬停，因此该代码块之外的规则会让它们无从触及。窄面板的规则必须让行换行并给标题一整行，因为让命令在触屏上常驻可见，会使单行放不下标题、日期和两个命令。同一个测试还会拒绝字面颜色和 `font-family`——本页读取官方 token，而不是复述它们。

还有一条规则管住排序：创建时间顺序只读 `createdAt`。拿行的 `updatedAt` 顶替它缺失的创建时间，会把子代理归档到它最近一次运行的时刻——本页知道这个事实，而读的人会误当成对话开始的时间。测试夹具让两种顺序的首行落在不同的行上，因此读错列的实现会失败而不是蒙混通过。

</details>

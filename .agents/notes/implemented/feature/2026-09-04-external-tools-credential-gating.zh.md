# Agent Note：凭据门控的外部工具

Status: implemented

[English](2026-09-04-external-tools-credential-gating.md) | 中文

## 问题

用户需要填写提供方 API Key 后启用工具的 Hermes 式体验，同时 DSH 必须避免把密钥写入普通设置、插件目录或会话日志。

## 决策

`@deepseek-ai/dsh-external-tools` 负责提供方目录和注册表。它通过 `dsh-credentials` 解析凭据，只把提供方状态和 endpoint 覆盖写入设置，并在凭据或启用状态变化时注册或释放工具。浏览器端增加本地化的“工具与连接”设置页；首版实现 Brave Search、Tavily、Firecrawl、Exa 和 GitHub 的 HTTP 工具，同时登记尚未支持的提供方但不暴露不可用工具。

## 曾考虑的替代方案

**把 API Key 写入普通设置。** 否决，因为设置经常会被导出并投影到客户端；凭据服务提供必要的密钥存储和脱敏路径。

**立即暴露目录中的所有提供方。** 否决，因为没有经过验证的后端时，目录条目会制造误导性的启用状态；尚未支持的提供方只作为延期配置元数据展示。

## 后果

配置好的提供方会在下一会话可用，密钥不会复制进模型可见上下文或持久化会话数据。提供方专属的连接测试、OAuth 以及媒体和浏览器后端留待后续实现；提供方错误会降级为不含密钥的状态诊断。

# Agent Note: Retry the latest safe assistant answer

Status: implemented

English | [中文](2026-09-21-interrupted-answer-retry.zh.md)

## Problem

An undesirable assistant answer left a durable settlement and nothing the reader could do about it: the Turn offered copy and branch only, and the sole "retry" in the product was the provider-failure retry policy. Resuming meant retyping the prompt or sending a literal "continue", which either duplicated the prompt or fed the previous answer back as new input. Neither produces the model history a regenerate needs: one replay of the original prompt, no shadowed answer, and the current model, effort, and permission configuration. The first retry attempt addressed only an interrupted surface `assistant/message`, so a stop that settled as a log-only `assistant/attempt` — a reasoning-only, zero-output, or partial stream with no surface message — kept the button hidden, and an answer that completed but disappointed the reader had no action at all.

## Decision

The Chat opening user message renders a Retry icon beside copy in its action row when the latest Turn of an idle Session closes on a single assistant answer and ran no tool call. Only an ordinary turn-opening user message — never a steering message — owns the replayable prompt, and only the latest loaded Turn offers the action. The closing answer may have settled as a surface `assistant/message` — interrupted, or an ordinary answer whose Turn ended `completed` — or as a log-only `assistant/attempt` when the stop arrived before any surface message; a reasoning-only stop counts, and a zero-output attempt still projects its stopped row so the action stays reachable. The button admits `session/retryInterrupted` with a durability-addressed target — the message id or the attempt's `seq` — and reports failure on the same action row.

The Host command requires an idle Agent and resolves the target from the Session's current surface and durable settlements. A message address requires the last surface node to be that `assistant/message`: an interrupted message is replayable whatever closed its Turn, while an ordinary answer requires the latest closed Turn to end `completed`. An attempt address requires the latest closed Turn to end `aborted` or crash-repaired `interrupted`, to carry that attempt as its only settlement, and to hold no `assistant/message`. In both cases the latest closed Turn must own the settlement, and within its surface range the resolver locates the replayable prompt — an ordinary `user/message` or a previous retry's `assistant-retry` — accepting only injected user-role context and system nodes between it and the surface end. Tool calls or results, a second assistant answer or attempt, a second replayable prompt, or no replayable prompt reject with `session/retry-unavailable`.

On acceptance the Host mints a new `user/message` whose content is the prompt's durable content (text and attachment references) and whose source is the merge-extensible `assistant-retry` kind carrying the same durable `retryOf` address. `retryOf` is a `MessageId | SessionInterruptedRetryTarget` reader: released 0.1.20 wrote the bare interrupted message id, current writers always write the address, and neither the Host resolver nor the Client projection depends on the value, so a legacy log replays unchanged. The Agent's one-shot `retryInterrupted(message, replacement)` capability stores a pending surface replacement and wakes the ordinary follow-up turn; the loop appends the first-attempt message with the replacement's `surfaceOp: { op: 'replace', startSeq, endSeq }` and complete `sourceEventSeqs` instead of an append. For a log-only attempt the replaced surface range ends at the Turn's last surface node and the attempt seq joins the cited sources. The new Turn therefore runs the ordinary pre-step, current request configuration, and streaming path, while derived history contains the replay exactly once and no previous answer. The append-only log keeps the replaced attempt for audit, and the replacement's provenance makes the retried answer retryable again.

The pending replacement is one-shot and never overwrites a live one: a rejected pre-step, a rewritten or emptied admitted batch, an admission throw, cancellation, and driver teardown all clear it. The Client keeps one admission per Session in flight, ignores a second click, and drops a settlement invalidated by a connection reset.

## Alternatives considered

**Send a literal "continue" or re-send the prompt through the composer.** Rejected: it appends a second user message, so the model sees the original prompt, the interrupted partial, and the new input. It also depends on the composer draft instead of the durable prompt.

**Append the replacement from the Host and wake with no admitted message.** Rejected: the loop closes a Turn whose first enter admits nothing, so the step would never run; a wake token that is appended normally duplicates the prompt.

**Replay the interrupted partial's content as the prompt.** Rejected: the partial is the answer, not the prompt; replaying it makes the model continue its own half sentence.

**Accept every candidate answer and let the Host reject at click time.** Rejected: a button that always fails is worse than none; the resolver rejects the ambiguous shapes up front.

**Hide the button whenever the Client cannot prove the exact Host condition.** Partially rejected: the Client's Turn data proves the no-tool, single-answer, latest-Turn shape, and the runtime-context case the Host now accepts. The residual — an automatic goal round or an extra ordinary user input in the Turn — is not visible to the Client's Turn-tail data, so that click reports `session/retry-unavailable` on the action row instead of hiding.

## Consequences

The action reuses the existing surface-replacement and provenance mechanism, so `SESSION_FORMAT_VERSION` is unchanged: the only new durable fact is a `user/message` replacement whose source is a merge-extensible `MessageSourceMap` entry, now read as a `MessageId | SessionInterruptedRetryTarget` provenance while current writers always write the address, so a released 0.1.20 log replays unchanged. The Agent gains an optional `retryInterrupted` capability; a driver without it reports `session/retry-unavailable`. The current surface tail, not a numeric span, defines the replaced range, so an injected runtime-context node between the prompt and the surface end is shadowed with it; a log-only attempt joins the cited sources. The Chat Assistant node rebuilds an interrupted prefix from a durable `assistant/attempt` stream, so a stopped answer survives cold replay; only the final attempt contributes that prefix, so a superseded attempt donates neither timing nor visible blocks to a later successful message, and an attempt that delivered no blocks still projects its interrupted row so a zero-output stop keeps its retry action. A Turn that ran tools, an attempt address whose Turn holds another settlement, a Turn with more than one surface assistant answer, a completed Turn whose end reason is not `completed`, or a Turn opened by anything other than a replayable prompt cannot be retried.

# Agent Note: 默认收起附件识别文本

Status: implemented

[English](2026-09-13-collapsed-attachment-recognition-text.md) | 中文

## 问题

Office 与 OCR 识别器会在持久附件旁把提取文本记录为模型可见文本块。Chat 过去会把这种内部表示与普通用户文本拼接起来，长文档因而产生巨大的用户气泡。会话标题服务也会把提取正文当成人类标题输入，因此只有文件的提示词可能以内置标记或文档内容作为标题。

## 决策

`dsh-llm` 负责既有 `[DeepSeek Files extracted text from …]` 表示的稳定编码器与 Host 侧解析器。Session Controller 与 Lark 使用编码器，Session Title 使用解析器。由于 Client 功能包不能导入 Host 功能值，Chat 渲染器在本包内识别同一已记录表示。两处解析器都接受当前及此前已记录的文本块，不改变 Session 格式或模型可见字节。

Chat 将识别出的附件文本与普通用户文本分开。每段识别正文都显示为附件旁的本地化收起项，并默认关闭；展开后可在有界滚动区域查看完整记录文本。用户消息复制操作只接收普通用户文本。

会话标题会从确定性回退和提供方输入中排除已解析的附件识别块。只含文件和识别文本的提示词保持无标题，直到后续出现普通人类文本。

## 考虑过的替代方案

**增加新的 Session 内容块类型。** 不予采纳，因为提取文本已有已发布、模型可见的表示。新类型需要改变 Session 格式，并更新每个适配器、SDK、压缩器、token 计量器与迁移，却不会改善已存信息。

**在 Chat 中截断或丢弃提取文本。** 不予采纳，因为用户必须能够检查识别器实际提供给模型的内容。默认收起能控制布局，而不会隐藏或修改证据。

**继续允许识别文本生成标题。** 不予采纳，因为它是机器派生输入，不代表用户的命名意图，而且可能淹没简短提示词，或成为只有文件的 Session 的完整标题。

## 后果

新旧识别文档保持相同的持久内容与模型可见内容，同时默认只占一行紧凑空间。用户可以展开完整提取结果，普通提示词文本仍可独立复制并用于标题。解析器保留确切的 DeepSeek Files 标记语法；手工输入同一语法的文本块也会得到相同的派生内容呈现。

聚焦的 LLM、Chat、Session Controller、Lark、迁移与会话标题测试固定编码兼容性、默认收起呈现、生产方输出和标题排除行为。
